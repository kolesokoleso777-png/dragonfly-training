DRAGONFLY TRAINING V10 — ПОДКЛЮЧЕНИЕ D1 (ТЕСТОВАЯ СБОРКА)

Что изменено:
- Существующий интерфейс и разделы V10 сохранены.
- Добавлены Pages Functions: /api/health и /api/data.
- Организация (ORG) и учебное состояние сотрудника/менеджера синхронизируются с D1.
- При первом подключении, если запись ещё отсутствует в D1, текущие локальные данные отправляются в базу.
- localStorage пока остаётся локальным кэшем/резервом, но загрузка и запись синхронизируются с сервером.

ПЕРЕД ТЕСТОМ
1. Не удаляйте и не переименовывайте существующую привязку D1 с переменной DB.
2. Убедитесь, что в D1 применён файл migrations/0001_initial.sql. Он создаёт таблицу app_records, необходимую API.
3. Загрузите содержимое этой папки в существующий проект Cloudflare Pages (включая папки functions/ и migrations/).
4. После развёртывания откройте адрес сайта + /api/health. Ожидаемый ответ: {"ok":true,"database":"connected",...}.
5. Откройте сайт на устройстве с существующими локальными данными первым. После синхронизации проверьте вход на втором устройстве.
6. Проверьте: изменение списка сотрудников, прохождение одного раздела/теста, обновление страницы и повторный вход со второго устройства.

ВАЖНО: ЭТО СБОРКА ДЛЯ КОНТРОЛИРУЕМОГО ТЕСТИРОВАНИЯ, НЕ ПРОДАКШЕН.
Текущий API данных ещё не проверяет пользовательские сессии на сервере и не разделяет
доступ по ролям. Не используйте с реальными персональными данными сотрудников. До
продуктивного запуска необходимо перенести проверку пароля менеджера и кода сотрудника
на сервер, выпускать серверные сессии и проверять права на каждую запись.

ПРИМЕЧАНИЕ О ДАННЫХ
Первое устройство, у которого в D1 ещё нет записи, переносит свои локальные данные.
Если в D1 уже есть данные, они загружаются поверх локальных данных. Поэтому не тестируйте
на нескольких устройствах с разными несинхронизированными наборами данных одновременно:
сначала выберите исходное устройство, откройте сайт и убедитесь, что /api/health работает.
